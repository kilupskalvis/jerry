# jerry generate

Compile `.jerry/` specs into native CI configuration files.

## Usage

```
jerry generate [flags]
```

## Description

Reads every workflow under `.jerry/`, validates the project, and emits one GitHub Actions workflow file per spec workflow to `.github/workflows/jerry-<name>.yml`.

Generated files include a preamble (checkout with full history, pinned Jerry install, pinned runtime install from `jerry.lock`, drift check) followed by one `jerry exec <wf>/<step>` invocation per step.

Output is byte-deterministic: the same spec and Jerry version always produce identical YAML. This is what makes `--check` a simple byte comparison.

## Flags

| Flag | Type | Default | Description |
|---|---|---|---|
| `--check` | bool | false | Regenerate in memory and compare to disk. Exit 2 if any file differs. |
| `--stdout` | bool | false | Print generated files to stdout instead of writing to disk. |
| `--backend` | string | `"github"` | Target CI platform: `github`, `gitlab`, or `all`. |

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Files written (or `--check` passed) |
| 1 | Error (spec invalid, write failure) |
| 2 | Drift detected (`--check` mode only) |

## Examples

Write CI config:

```bash
$ jerry generate
jerry: wrote .github/workflows/jerry-review.yml
jerry: wrote .github/workflows/jerry-feature.yml
```

Check for drift (typically run in CI):

```bash
$ jerry generate --check
jerry: all generated files up to date
```

Preview without writing:

```bash
$ jerry generate --stdout
--- .github/workflows/jerry-review.yml ---
# GENERATED BY JERRY vdev FROM .jerry/review/ — DO NOT EDIT.
...
```

Generate GitLab CI config:

```bash
$ jerry generate --backend gitlab
jerry: wrote .gitlab-ci-jerry.yml
```

Generate both platforms:

```bash
$ jerry generate --backend all
jerry: wrote .github/workflows/jerry-review.yml
jerry: wrote .github/workflows/jerry-feature.yml
jerry: wrote .gitlab-ci-jerry.yml
```

## Drift detection

`jerry generate --check` is compiled into every generated workflow as the first real step. This catches hand-edits to generated files: they survive locally but fail loudly on the next CI run. Edit the spec and re-run `jerry generate` instead.
